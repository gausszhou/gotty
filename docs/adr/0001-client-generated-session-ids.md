# 会话 id 由客户端生成,设备本地清单成为列表的唯一来源

曾由服务端生成会话 id 并保存全量列表(旧 `GET /api/sessions` + `GET /api/sessions/history`);现改为:客户端生成 16 位 base36 会话 id,设备把会话清单保存在 localStorage(`gotty.sessions`),服务端只按 id 保留记录供复活、不再提供列表端点。

理由:多设备共享一台服务时,设备间的会话必须互不抢占、互不依赖——各设备用各自生成的 id,只有"相同 id"(如刷新、粘帖他人 id)才复用同一会话。随之而来的是客户端生成 id + 设备清单,单测/双客户端 e2e 验证(幂等、复活、status、抢占)。

备选:保持服务端列表,由服务端按 id 记录归属设备。该方案仍需要跨设备同步清单,且服务端列表端点会成为"谁的会话"的歧义来源;客户端生成 id 让会话身份完全由持有 id 的人决定,与抢占语义天然一致。旧会话记录文件(数组格式)在加载时自动迁移为 map[id] 并原子重写。
